# 언리얼 컨테이너 개요

> 언리얼 엔진에서 제공하는 템플릿 기반 자료구조. 앞에 붙는 `T`는 Template의 약자로, 어떤 타입이든 호환한다.

---

## 세 줄 요약

- **[[TArray]]** — 순서가 있는 배열. 인덱스 접근이 빠르고, 순회가 빠르다.
- **[[TSet]]** — 순서 없음, 중복 없음. 탐색·삽입·삭제가 빠르다.
- **[[TMap]]** — Key-Value 쌍. 키로 값을 즉시 찾을 수 있다.

---

## 성능 비교표

| 연산 | TArray (Vector 기반) | TSet / TMap (Hash 기반) |
|---|---|---|
| **접근** | **O(1)** — 인덱스로 즉시 이동 | **O(1)** — 해시 계산 후 즉시 이동 |
| **탐색** | **O(n)** — 처음부터 끝까지 순회 | **O(1)** — 키/값으로 바로 점프 |
| **삽입** | **O(n)** — 끝에 붙이면 빠르지만 중간은 밀어야 함 | **O(1)** — 빈 칸 찾아 바로 삽입 |
| **삭제** | **O(n)** — 지우고 빈틈 메워야 함 | **O(1)** — 해당 칸만 제거 |

---

## 메모리 구조 차이

### TArray — 연속 메모리

```
[10][20][30][40][50]
 ↑ 따닥따닥 붙어있음 → 인덱스 접근 빠름
```

중간 삭제 시 뒤의 요소를 전부 앞으로 당겨야 함.

### TSet / TMap — 비연속 메모리 (해시 테이블)

```
[10][구멍][30][40][50]
 ↑ 삭제하면 구멍이 남음 → 순서 보장 안 됨, 인덱스 접근 불가
```

새 요소 추가 시 구멍을 재활용. 구멍이 많아지면 `Compact()` + `Shrink()`로 정리.

---

## 해시 테이블이란?

사물함 비유:

- **일반 배열**: 과자를 찾으려면 모든 사물함을 열어봐야 함
- **해시 테이블**: Key(열쇠 번호)가 있으면 해당 사물함을 바로 열어서 가져감

Key를 통해 데이터가 저장된 위치를 직접 계산하므로, 탐색·삽입·삭제가 모두 O(1).

---

## 언제 뭘 쓸까?

| 상황 | 선택 |
|---|---|
| 순서가 중요하고 인덱스로 접근해야 할 때 | [[TArray]] |
| 중복 없이 빠르게 존재 여부를 확인할 때 | [[TSet]] |
| 키로 값을 빠르게 찾아야 할 때 (인벤토리, 아이템 ID 등) | [[TMap]] |
