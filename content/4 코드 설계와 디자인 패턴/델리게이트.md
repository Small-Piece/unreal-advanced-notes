# 델리게이트

> "나 이런 일이 일어났어!"라고 방송하면, 듣고 있던 애들이 각자 할 일을 하는 이벤트 시스템. 강한 결합을 끊어준다.

---

## 왜 쓰나? — 강한 결합 끊기

보스 몬스터가 죽을 때 여러 일이 일어나야 한다:

- 잡몹 제거
- 아이템 회수
- 배경음악 끄기
- 경험치 부여

### ❌ 델리게이트 없이

```
보스 사망 → 보스가 직접 잡몹 찾아서 제거
         → 보스가 직접 아이템 찾아서 회수
         → 보스가 직접 음악 끄기
         → 보스가 직접 경험치 부여
```

보스 구현부가 다른 모든 시스템에 의존하게 됨. 강한 결합.

### ✅ 델리게이트로

```
보스: "나 죽었어!" 라고 방송(Broadcast)만 함
잡몹/아이템/음악/경험치: 각자 듣고 있다가 신호 오면 자기 할 일만 함
```

보스는 누가 듣는지 알 필요도 없다. 느슨한 결합. [[인터페이스]]와 함께 결합도를 낮추는 핵심 도구.

## 선언 유형

> `DECLARE_[유형]_DELEGATE_[함수정보]`

|유형|매크로|특징|
|---|---|---|
|1:1, C++ 전용|`DECLARE_DELEGATE`|반환값 가능|
|1:다, C++ 전용|`DECLARE_MULTICAST_DELEGATE`|반환값 불가|
|1:1, 블루프린트 지원|`DECLARE_DYNAMIC_DELEGATE`|리플렉션 기반|
|1:다, 블루프린트 지원|`DECLARE_DYNAMIC_MULTICAST_DELEGATE`|가장 많이 씀|
|바인딩 전까지 메모리 0|`DECLARE_SPARSE_DELEGATE`|거의 안 쓰이면 효율적|

### 함수 정보 (매개변수/반환값)

|상황|접미사|
|---|---|
|인자 없음, 반환값 없음|(공란)|
|인자 1개, 반환값 없음|`_OneParam`|
|인자 3개, 반환값 있음|`_RetVal_ThreeParams`|

> **MULTICAST는 반환값을 지원하지 않는다.** (여러 함수가 각각 다른 값을 반환하면 어느 걸 받을지 모호하므로)

```cpp
// 1:다, 블루프린트 지원, 인자 1개
DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FHealthDeadSignature, AController*, Instigator);

// 1:다, 블루프린트 지원, 인자 3개
DECLARE_DYNAMIC_MULTICAST_DELEGATE_ThreeParams(FHealthDamagedSignature,
    float, NewHealth, float, MaxHealth, float, HealthChange);
```

## 바인딩 (신호 듣기)

신호를 듣겠다고 등록하는 것. **싱글캐스트는 `Bind`, 멀티캐스트는 `Add`**로 시작.

|바인딩 함수|대상|안전성|
|---|---|---|
|`BindUObject` / `AddUObject`|UObject 기반 (Actor, Component)|**가장 권장.** GC로 파괴되면 호출 안 함|
|`BindSP` / `AddSP`|TSharedPtr 기반|참조 카운트로 생존 확인|
|`BindLambda` / `AddLambda`|람다|캡처 수명 주의|
|`BindStatic`|전역/정적 함수|항상 안전|
|`BindUFunction` / `AddDynamic`|UFUNCTION 함수|느리지만 직렬화/블루프린트 연동 가능|

### Native vs Dynamic

|구분|싱글|멀티캐스트|
|---|---|---|
|C++ 전용 (Native)|`BindUObject`, `BindSP`, `BindLambda`|`AddUObject`, `AddSP`, `AddLambda`|
|블루프린트 연동 (Dynamic)|`BindDynamic`, `BindUFunction`|`AddDynamic`|

> **Dynamic은 함수에 반드시 `UFUNCTION()`을 붙여야 한다.** 함수 이름을 문자열로 찾아 바인딩하기 때문.

> `AddDynamic` vs `AddUniqueDynamic`: Unique는 중복 바인딩을 막아주지만 매번 검사해서 약간 느림. 관리에 자신 있으면 `AddDynamic`.

## 호출 (신호 보내기)

|구분|함수|특징|
|---|---|---|
|싱글캐스트|`Execute()` / `ExecuteIfBound()`|하나만 실행, 반환값 가능|
|멀티캐스트|`Broadcast()`|등록된 모두 실행, 반환값 없음|

### 안전성 차이

```cpp
// ⚠️ 싱글캐스트: 바인딩 안 되어 있으면 크래시!
if (MySingleDelegate.IsBound())
{
    MySingleDelegate.Execute(Param);
}
MySingleDelegate.ExecuteIfBound(Param);  // 더 안전

// ✅ 멀티캐스트: 바인딩 없어도 안전
OnDeath.Broadcast(KillerActor);
```

## 블루프린트에서 받으려면

```cpp
public:
    // 1. public 으로 선언
    // 2. UPROPERTY + BlueprintAssignable
    UPROPERTY(BlueprintAssignable, Category = "Events")
    FHealthDeadSignature OnHealthDead;
```

## 실전 예시: 체력 컴포넌트

```cpp
// 선언
DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FHealthDeadSignature, AController*, Instigator);

UPROPERTY(BlueprintAssignable)
FHealthDeadSignature OnHealthDead;
```

```cpp
// BeginPlay에서 데미지 신호를 받겠다고 바인딩
GetOwner()->OnTakeAnyDamage.AddDynamic(this, &UMyActorComponent::DamageTake);

// 데미지를 받으면 처리하고, 죽으면 OnHealthDead 방송
void UMyActorComponent::DamageTake(AActor* DamagedActor, float Damage, ...)
{
    _CurrentHealth -= FMath::Min(Damage, _CurrentHealth);
    OnHealthDamaged.Broadcast(_CurrentHealth, _MaxHealth, FinalDamage);

    if (_CurrentHealth == 0.f)
    {
        OnHealthDead.Broadcast(Instigator);  // "나 죽었어!" 방송
    }
}
```

```cpp
// 다른 곳에서 사망 신호 듣기
HealthComponent->OnHealthDead.AddDynamic(this, &ATestMyActor::HandleActorDead);

void ATestMyActor::HandleActorDead(AController* InstigatorController)
{
    // 사망 시 할 일
}
```

플레이어 사망 시 [[인터페이스]] 실습에서 만든 아이템들을 전부 Destroy하는 것도, 각 아이템이 `OnHealthDead`를 구독하면 보스/플레이어 쪽 코드를 건드리지 않고 구현된다.
