# 코드 스멜과 리팩토링

> 코드에서 나는 "냄새" — 당장 에러는 아니지만, 방치하면 유지보수가 어려워지는 구조적 문제들

---

## 뒤엉킨 변경 (Divergent Change)

한 클래스가 **여러 이유**로 자주 수정되어야 하는 상태. 단일 책임 원칙 위반.

```cpp
// ❌ GameManager가 데이터도, 게임플레이도 담당
// ✅ UPlayerDataManager / UGameplayManager 로 분리
```

---

## 샷건 수술 (Shotgun Surgery)

작은 변경 하나를 위해 **여러 클래스를 동시에 수정**해야 하는 상태.

```cpp
// ❌ 데미지 로직이 Character, Weapon, GameMode 3곳에 분산
// ✅ UDamageSystem 한 곳에 모음
```

---

## 기능 편애 (Feature Envy)

어떤 함수가 **자기 객체보다 남의 객체 데이터**와 더 많이 소통하는 상태. 데이터가 있는 곳으로 옮기자.

```cpp
// ❌ DamageCalculator가 Character 데이터를 잔뜩 가져다 계산
// ✅ Character가 자기 데이터로 직접 계산
```

---

## 데이터 뭉치 (Data Clumps)

자주 함께 쓰이는 데이터가 **낱개 매개변수**로 반복되는 상태. 구조체로 묶자.

```cpp
// ❌
void FireWeapon(float Damage, float Range, float Accuracy);

// ✅
USTRUCT(BlueprintType)
struct FWeaponStats { float Damage; float Range; float Accuracy; };
void FireWeapon(const FWeaponStats& Stats);
```

---

## 기본형 집착 (Primitive Obsession)

복잡한 개념을 `float`, `FString` 같은 기본형에 과도하게 의존하는 상태. 전용 타입을 만들면 로직과 검증이 한 곳에 모인다.

```cpp
// ❌ float Health; float MaxHealth; (음수/초과 버그를 매번 체크)

// ✅ FHealth 클래스 — Clamp, ApplyDamage를 내부에서 안전하게 처리
class FHealth
{
    FHealth(float InCurrent, float InMax)
        : Current(FMath::Clamp(InCurrent, 0.f, InMax)), Max(InMax) {}
    void ApplyDamage(float Amount) { Current = FMath::Max(0.f, Current - Amount); }
};
```

## 반복되는 스위치문 (Repeated Switches)

새 분기가 생길 때마다 여러 switch문을 전부 수정해야 하는 상태. **다형성**으로 해결.

```cpp
// ❌ switch (WeaponType) { case Sword: ...; case Bow: ...; }

// ✅ 다형성 — 각 무기가 Attack()을 override, 호출부는 switch 없음
EquippedWeapon->Attack();
```

→ 이 원칙의 발전형이 [[템플릿 패턴과 샌드박스 패턴]]

## 반복문 (Loops)

루프 안에 비즈니스 로직을 다 욱여넣지 말자. 기능별로 함수로 쪼개서 **책의 목차처럼 읽히게** 만들자.

### ❌ 나쁜 예시 — 한 함수에 필터링·계산·판정이 뒤섞임

```cpp
void ProcessHeavyItems()
{
    // (1) 무거운 아이템 골라내기 (for문)
    // (2) 무게 총합 계산 (for문)
    // (3) 기준 초과 시 효과 적용 (if문)
    // ... 전부 한 함수에
}
```

### ✅ 좋은 예시 — 의도가 드러나는 함수로 분리

```cpp
void ProcessHeavyItems()
{
    TArray<UItem*> Items = GetAllItems();
    TArray<UItem*> HeavyItems = GetHeavyItems(Items);
    float TotalWeight = GetTotalWeight(HeavyItems);

    if (IsTooHeavy(TotalWeight))
    {
        ApplySlowEffect();
    }
}
// GetHeavyItems, GetTotalWeight, IsTooHeavy 각각 별도 함수
```

본문만 읽어도 "아이템 가져와서 → 무거운 것만 골라 → 총무게 재서 → 너무 무거우면 효과 적용"이 한눈에 읽힌다.

## 게으른 요소 (Lazy Element)

하는 일 없이 **호출만 전달**하는 메서드나 클래스는 혼동만 준다. 과감히 삭제하자.

```cpp
// ❌ Launch가 LaunchProjectile을 호출만 함 (중간 함수 불필요)
void Launch(const FVector& Dir, float Speed) { LaunchProjectile(Dir, Speed); }

// ✅ 바로 구현
void Launch(const FVector& Dir, float Speed)
{
    ProjectileMovement->Velocity = Dir * Speed;
}
```

## 추측성 일반화 (Speculative Generality)

"나중에 필요할 수도 있어"라며 미리 만든 코드는 대부분 짐이 된다. **현재 문제 해결이 우선.**

```cpp
// ❌ 안 쓰는 가상 함수와 매개변수를 잔뜩 선언
virtual void SpecialAttack();   // 안 씀
virtual void UltimateAttack();  // 안 씀
void SetDamage(float Base, float Crit, float Splash, float Chain, float Summon);

// ✅ 필요한 것만, 확장은 필요할 때 상속으로
class AWeapon { void Attack(); void SetDamage(float InDamage); };
class AMagicWeapon : public AWeapon { void ElementalAttack(); };
```
