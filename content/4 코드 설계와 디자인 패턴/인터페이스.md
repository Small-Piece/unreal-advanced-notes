# 인터페이스

> "이 기능을 할 수 있다"는 능력만 약속하는 계약서. 상속 없이 서로 다른 클래스에 공통 기능을 부여하는 도구.

---

## 왜 쓰나? — 느슨한 결합

플레이어가 다양한 물체(문, 소화기, 보물상자, NPC)와 상호작용한다고 하자.

- **일일이 캐스팅**: `if (Cast<ADoor>) ... else if (Cast<AChest>) ...` → 코드가 끝없이 길어짐
- **상속으로 해결**: 자식이 너무 많아지고, 상호작용 안 하는 클래스에는 불필요한 기능이 강제됨

### 다중 상속 문제

> 언리얼의 UObject는 **다중 상속을 지원하지 않는다.** 자식은 부모를 하나만 가질 수 있다.

인터페이스는 **여러 개를 동시에 추가**할 수 있어서 이 한계를 우회한다.

---

## U타입과 I타입

인터페이스를 만들면 클래스가 두 개 생성된다:

|타입|역할|
|---|---|
|`UTestMyInterface` (U타입)|[[리플렉션]] 시스템에 인터페이스의 존재를 알림|
|`ITestMyInterface` (I타입)|실제 함수를 선언하고, 클래스가 상속받아 구현|

> I타입은 순수 C++ 클래스 형태라서, 여러 개의 I타입 인터페이스를 동시에 상속받을 수 있다.

---

## 기본 구현 (순수 가상함수)

```cpp
// 인터페이스 선언
class ITestMyInterface
{
    GENERATED_BODY()
public:
    virtual void OnFireDetected(float Temperature, FVector HitLocation) = 0;  // 순수 가상함수
};
```

```cpp
// 불에 타는 Cloth만 인터페이스 상속
UCLASS()
class AItem_Cloth : public AItemBase, public ITestMyInterface
{
    GENERATED_BODY()
public:
    virtual void OnFireDetected(float Temperature, FVector HitLocation) override;
};
```

> 순수 가상함수(`= 0`)를 구현하지 않으면 **abstract 오류**가 난다.

### 호출하는 쪽

```cpp
for (const TWeakObjectPtr<AActor>& Item : Items)
{
    ITestMyInterface* MyInterface = Cast<ITestMyInterface>(Item.Get());
    if (MyInterface)
    {
        MyInterface->OnFireDetected(100.0f, FVector::ZeroVector);
    }
}
```

돌(Steel)은 인터페이스가 없으니 Cast 결과가 nullptr → 자동으로 걸러진다. 인터페이스가 없었다면 물체별로 일일이 캐스팅해야 했을 것.

## 블루프린트까지 지원하기

위 방식은 **블루프린트에서 추가한 인터페이스를 못 잡는다.** 해결하려면 두 가지를 바꿔야 한다.

### 1. 인터페이스에 BlueprintNativeEvent

```cpp
class ITestMyInterface
{
    GENERATED_BODY()
public:
    // BlueprintNativeEvent → 블루프린트 구현이 있으면 우선, 없으면 C++ 실행
    UFUNCTION(BlueprintCallable, BlueprintNativeEvent, Category = "Interaction")
    void OnFireDetected(float Temperature, FVector HitLocation);
};
```

### 2. 구현 클래스는 _Implementation 접미사

```cpp
// virtual + override + _Implementation
virtual void OnFireDetected_Implementation(float Temperature, FVector HitLocation) override;
```

### 3. 호출은 Execute_ + DoesImplementInterface

```cpp
#include "Kismet/KismetSystemLibrary.h"

for (const TWeakObjectPtr<AActor>& Item : Items)
{
    if (UKismetSystemLibrary::DoesImplementInterface(Item.Get(), UTestMyInterface::StaticClass()))
    {
        ITestMyInterface::Execute_OnFireDetected(Item.Get(), 100.0f, FVector::ZeroVector);
    }
}
```

---

## virtual + BlueprintNativeEvent 충돌

`BlueprintNativeEvent`나 `BlueprintImplementableEvent`은 [[UHT (Unreal Header Tool)]]가 함수 본문을 대신 만들어준다. 이때 `virtual`을 직접 붙이면 충돌한다.

- **C++**: "이 함수는 가상함수니 자식 메모리 뒤져서 실행해!"
- **UHT**: "잠깐, 블루프린트에 구현이 있을 수도 있잖아. 내가 확인할 테니 비켜봐."

그래서 인터페이스 선언부에서는 함수 본문을 작성하면 안 된다. UHT가 가져가서 관리하기 때문.

---

## Execute_ 호출 시 주의

`Execute_OnFireDetected`는 편하지만 **호출 안전성이 보장되지 않는다**:

- UObject를 받기 때문에 아무 객체나 넣을 수 있음 (잘못된 객체를 못 잡아냄)
- private로 선언해도 외부에서 호출 가능
- nullptr이나 해제된 메모리면 크래시

→ 반드시 `DoesImplementInterface`로 안전 체크를 먼저 하자.
