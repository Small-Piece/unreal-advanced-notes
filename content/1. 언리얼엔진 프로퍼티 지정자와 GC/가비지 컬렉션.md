# 가비지 컬렉션

> 언리얼 엔진이 더 이상 쓰이지 않는 UObject를 자동으로 찾아 메모리에서 제거하는 시스템

---

## 비유: 교실 청소부

약 30~60초마다 교실에 청소부 아저씨(GC)가 들어와서 확인한다:

**"이 물건, 아직 누가 쓰고 있어?"**

---

## 동작 과정 (4단계)

### 1단계: 뿌리에서 출발 (Root Set)

절대 지우면 안 되는 핵심 객체(World, GameInstance 등)에서 시작한다. 교실의 교탁, 칠판에 해당.

### 2단계: 이름표 줄 따라가기 (마킹)

[[UPROPERTY]]로 연결된 다른 객체들을 하나씩 따라간다. "교탁 → 출석부 → 교무수첩" 이렇게 줄줄이 따라가면서 "아직 쓰는 물건"이라고 체크.

### 3단계: 고립된 객체 판정

줄을 전부 따라간 뒤에도 아무 줄에도 연결 안 된 물건이 있으면? "아무도 안 쓰는 쓰레기구나!"

### 4단계: 제거

고립된 객체를 메모리에서 삭제한다.

---

## 핵심 규칙

> **UObject 포인터를 멤버 변수로 들고 있으려면, 반드시 [[UPROPERTY]]를 붙여야 한다.**

```cpp
// ✅ 안전 — GC가 추적하고, 삭제 시 nullptr로 정리해줌
UPROPERTY()
UMyTestObject* SafeObject;

// ❌ 위험 — GC가 모르므로 언제든 삭제될 수 있음
UMyTestObject* DangerObject;
```

함수 안의 지역 변수(로컬 포인터)는 UPROPERTY가 필요 없다. 한 프레임 안에서 쓰고 끝나니까.

---

## GC와 스마트 포인터의 관계

| 비교 항목 | 가비지 컬렉션 | C++ SharedPtr |
|---|---|---|
| 대상 | UObject 상속 클래스만 | 일반 C++ 객체 |
| 관리 주체 | 언리얼 엔진이 자동 | 참조 카운트 기반 자동 |
| 언리얼 버전 | 기본 내장 | `TSharedPtr` |

"GC가 있는데 TSharedPtr은 왜 쓰나요?" → GC는 UObject만 관리한다. 외부 라이브러리 객체처럼 UObject를 상속받지 않은 클래스는 TSharedPtr로 관리해야 한다.

---

## 삭제 과정: 2단계 파괴

GC가 객체를 삭제할 때 한 프레임에 한꺼번에 지우지 않는다:

```
BeginDestroy() → "삭제 준비 시작"
FinishDestroy() → "메모리에서 완전히 제거"
```

```cpp
// BeginDestroy / FinishDestroy 오버라이드로 확인 가능
virtual void BeginDestroy() override
{
    Super::BeginDestroy();
    UE_LOG(LogTemp, Warning, TEXT("GC 시작: %s 삭제 준비"), *GetName());
}

virtual void FinishDestroy() override
{
    Super::FinishDestroy();
    UE_LOG(LogTemp, Error, TEXT("GC 완료: %s 메모리에서 제거"), *GetName());
}
```
