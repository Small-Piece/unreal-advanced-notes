# 댕글링 포인터와 안전한 참조

> [[가비지 컬렉션]]이 객체를 삭제한 뒤, 이미 무효화된 메모리 주소를 여전히 들고 있는 상태

---

## 비유: 빈 사물함 열쇠

사물함(메모리)은 이미 비워졌는데, 열쇠(포인터)에는 여전히 예전 번호가 적혀 있다. 이 열쇠로 문을 열면 엉뚱한 물건이 나오거나, 아예 문이 부서진다(크래시).

---

## 왜 발생하는가?

[[UPROPERTY]]가 없는 포인터는 GC가 관리하지 않는다. GC가 객체를 삭제해도 포인터 값을 `nullptr`로 밀어주지 못한다.

```cpp
UPROPERTY()
UMyTestObject* SafeObject;      // GC 삭제 후 → nullptr로 정리됨

UMyTestObject* DangerObject;     // GC 삭제 후 → 주소값 그대로 남아있음!
```

---

## 검증 방법 비교

| 검사 방법 | 하는 일 | UPROPERTY 있을 때 | UPROPERTY 없을 때 |
|---|---|---|---|
| `if (Obj)` | 주소값이 0(Null)인지만 확인 | GC 후 **false** | GC 후에도 **true** ⚠️ |
| `IsValid(Obj)` | Null 체크 + Pending Kill 체크 | GC 후 **false** | 신뢰할 수 없음 |
| `IsValidLowLevel()` | 진짜 유효한 UObject인지 확인 | GC 후 **false** | GC 후 **false** |

> **가장 위험한 구간**: `if (DangerObject)` 는 true를 반환하지만, 실제로 접근하면 크래시!

---

## 실험: 10초 뒤 크래시

```cpp
// 10초 뒤에 이미 GC된 DangerObject에 접근 시도
void AMyGCObserver::TryToUseObjects()
{
    DangerObject->InitObject(TEXT("펑."));  // 💥 크래시!
}
```

---

## 해결 방법

### 방법 1: UPROPERTY를 붙인다 (정석)

```cpp
UPROPERTY()
UMyTestObject* SafeObject;
```

- GC가 삭제 시 포인터를 `nullptr`로 정리해줌
- 가장 간단하고 안전한 방법
- 해당 객체를 "살려두고 싶을 때" 사용

### 방법 2: TWeakObjectPtr (약한 참조)

```cpp
TWeakObjectPtr<UMyTestObject> WeakObject;

// 안전한 접근
if (WeakObject.IsValid())
{
    WeakObject->DoSomething();
}
```

- 객체를 살려두지는 않음 (GC 삭제를 막지 않음)
- 대신 객체가 죽으면 `IsValid()`가 자동으로 `false` 반환
- "살았는지 죽었는지만 궁금할 때" 사용
- 비유: "열쇠는 있지만, 사물함이 비었으면 알아서 포기하는 똑똑한 열쇠"

---

## 언제 뭘 쓸까?

| 상황 | 선택 |
|---|---|
| 이 객체가 절대 삭제되면 안 돼 | `UPROPERTY()` 포인터 |
| 다른 누군가가 관리하는 객체를 참조만 할 거야 | `TWeakObjectPtr` |
| 함수 안에서 잠깐 쓰고 끝 | 일반 포인터 (로컬 변수) |
